# Development guide

## Everyday commands

```bash
docker compose up --build        # start everything (rebuild images)
docker compose up -d             # start in the background
docker compose logs -f backend   # follow one service's logs
docker compose ps                # service status / health
docker compose down              # stop (data is kept in Docker volumes)
docker compose down -v           # stop AND delete all data (fresh database)
```

## Database migrations (Alembic)

The backend container runs `alembic upgrade head` automatically on start.

```bash
# After changing SQLAlchemy models (they must be imported in backend/app/models/__init__.py)
docker compose exec backend alembic revision --autogenerate -m "add users table"
docker compose exec backend alembic upgrade head
docker compose exec backend alembic downgrade -1
```

Always read an autogenerated migration before committing it.

## Backend

```bash
docker compose exec backend pytest        # tests
docker compose exec backend ruff check .  # lint
docker compose exec backend ruff format . # format
```

Health endpoints:

- `GET /api/v1/health` - liveness (process is up, checks nothing else).
- `GET /api/v1/health/ready` - readiness: checks PostgreSQL (+ pgvector extension), Redis and MinIO.
  Returns **200** when all are up and **503** when any is down (same JSON body, with per-component detail).

All API errors use one shape: `{"error": {"code": "...", "message": "...", "details": null}}`.

## Frontend

The frontend container runs `next dev`. To add shadcn/ui components:

```bash
docker compose exec frontend npx shadcn@latest add button
```

If you change `package.json`, rebuild and refresh the anonymous `node_modules` volume:

```bash
docker compose up --build --renew-anon-volumes frontend
```

## Ports

Published on your machine (change in `.env` if they clash):

| Service | Port |
|---|---|
| Frontend | 3000 |
| Backend | 8000 |
| PostgreSQL | **5433** (not 5432, so it never clashes with a locally installed PostgreSQL) |
| Redis | 6379 |
| MinIO API / console | 9000 / 9001 |

Connect a DB tool from your machine to `localhost:5433` with the credentials from `.env`.
Inside Docker, services use their service names (`postgres`, `redis`, `minio`).

## Troubleshooting

**`error while interpolating` / variable is not set** - you have not created `.env`. Run `cp .env.example .env`.

**Port already in use** - change the matching `*_HOST_PORT` in `.env` (and `NEXT_PUBLIC_API_URL` / `BACKEND_CORS_ORIGINS` if you moved the backend or frontend).

**Changed the Postgres password but login fails** - the password is only applied when the data volume is first created. Run `docker compose down -v` to start fresh.

**MinIO image cannot be pulled** - MinIO has changed how it distributes images. Set `MINIO_IMAGE` in `.env` to another tag or registry (for example `quay.io/minio/minio:<tag>`).

**Frontend says it cannot reach the backend** - run `docker compose ps`, check the backend is `healthy`, and open http://localhost:8000/api/v1/health directly.

**Hot reload does not pick up changes on Windows** - polling is already enabled. For best speed keep the repository inside the WSL2 filesystem (e.g. `\\wsl$\Ubuntu\home\you\learnless-ai`) rather than under `C:\`.

**Shell scripts fail with `\r` errors in containers** - line endings. `.gitattributes` forces LF; re-clone or run `git add --renormalize .`.
